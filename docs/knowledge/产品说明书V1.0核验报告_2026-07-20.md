# CheersAI FileBay 产品说明书 V1.0 核验报告

- 核验日期：2026-07-20
- 核验基准：《CheersAI-FileBay 产品说明书·非技术版 V1.0》
- 核验对象：当前 `codex/integrate-ragflow-monorepo` 分支与本机内部试用环境
- 核验方式：源码、部署编排、只读运行检查与现有测试代码审查；未写入业务数据，未执行真实凭据操作。

## 一、结论

当前交付可定位为：**“FileBay 知识治理 + 受控 RAG 检索的白名单内部试用版”**。

它已具备受控资料入库、六项审核、发布与撤回、RAGFlow 索引适配、检索结果二次校验、基础审计，以及 Dify 外部检索接口等核心闭环能力。它**尚不能**按产品说明书 V1.0 宣称为完整的企业级知识中枢，也**不具备生产放行条件**。

产品说明书描述的是目标产品蓝图；当前实现覆盖其首期治理和检索主链路，而非全部十项能力中心。

## 四、已复核的高优先级整改项

### P0：不得作为生产环境放行

1. **RAGFlow 专用密钥的运行时落盘风险**：本机 Git 忽略的运行配置包含明文密钥。该内容未进入 Git，也未在本报告展示；应立即轮换该专用密钥，并改为受控文件挂载或密钥服务注入，同时收紧运行目录和备份访问权限。
2. **缺少生产运行保障**：未核验 TLS、备份恢复、灾备、容量、资源限制、健康检查、告警、RTO/RPO/SLO 与演练记录。
3. **Dify 闭环未完成验收**：接口存在不等于 Dify 已交付；需启动 Dify 并完成“Dify → FileBay → RAGFlow”的授权、撤回、过期和错误令牌回归。
4. **生产门禁测试未形成通过证据**：本机没有 Go 工具链，目标 Go 测试无法运行；本报告不把静态存在的测试当作通过结果。

### P1：内部试用体验与一致性

1. 已统一 RAGFlow 管理工作区地址为 `http://127.0.0.1:13080/ragflow/`；不再使用或发布旧的 `19080` 浏览器端口。
2. Dify 的 nginx 与插件调试端口已在试用编排中明确清空；Dify 作为可选私网调用方，不再形成第二个浏览器入口。
3. 模型供应商页面可配置模型，但当前未形成“嵌入模型已配置、索引可用、故障降级有效”的可重复验收记录。

## 五、建议的验收与推进顺序

1. 完成 P0 密钥整改与轮换，不在配置文件持久化服务端密钥。
2. 统一文档和编排端口语义，明确 Dify 是否纳入本期内部试用。
3. 在合成脱敏数据上执行并留档：资料提交 → 六项审核 → 发布 → RAGFlow 解析/索引 → FileBay 检索/引用 → 撤回/过期阻断 → Dify 调用。
4. 补齐跨账号、跨空间、过期、下架、无效令牌、RAGFlow 不可用和重试的自动化与人工验收记录。
5. 通过试用门禁后，再以业务优先级扩展连接器、知识图谱、智能体、质量运营和行业场景；不要将上游 RAGFlow 原生功能直接计入 FileBay 已治理能力。

## 六、核验限制

- 本次只使用本机合成脱敏环境，未访问真实业务数据或凭据。
- 未执行真实 Dify 链路，因为 Dify 容器未运行。
- 未运行 Go 目标测试，因为宿主机未安装 Go；不得据此声称测试已通过。
- RAGFlow 的解析、模型、智能体等上游能力只有在被 FileBay 的权限、生命周期和审计链路覆盖后，才能作为 CheersAI FileBay 的正式受控能力对外承诺。
