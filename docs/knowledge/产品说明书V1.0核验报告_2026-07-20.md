# CheersAI FileBay 产品说明书 V1.0 核验报告

- 核验日期：2026-07-21
- 核验基准：《CheersAI-FileBay 产品说明书·非技术版 V1.0》
- 核验对象：当前 `codex/integrate-ragflow-monorepo` 分支与本机内部试用环境
- 核验方式：源码、部署编排、只读运行检查与现有测试代码审查；未写入业务数据，未执行真实凭据操作。

## 一、结论

当前交付可定位为：**“FileBay 知识治理 + 受控 RAG 检索的白名单内部试用版”**。

它已具备受控资料入库、六项审核、发布与撤回、RAGFlow 索引适配、检索结果二次校验、基础审计，以及 Dify 外部检索接口等核心闭环能力。它**尚不能**按产品说明书 V1.0 宣称为完整的企业级知识中枢，也**不具备生产放行条件**。本轮真实检索还确认：RAGFlow 当前缺少可用的嵌入模型供应商，故“FileBay 返回实际引用”这一最终验收不能判为通过。

产品说明书描述的是目标产品蓝图；当前实现覆盖其首期治理和检索主链路，而非全部十项能力中心。

## 四、已复核的高优先级整改项

### P0：不得作为生产环境放行

1. **嵌入模型未就绪，真实检索未通过**：RAGFlow 的数据集引用 `BAAI/bge-small-en-v1.5@default@Builtin`，但该 Provider 未配置。必须在 RAGFlow 的“模型提供商”中配置并验证可用的嵌入模型，随后重新执行 FileBay 检索验收。
2. **既有 RAGFlow 专用密钥必须轮换**：新编排不再通过环境变量或 `app.ini` 持久化该密钥，改用只读受控文件挂载；此前可能暴露过的试用密钥仍应立即轮换。
3. **缺少生产运行保障**：尚未核验 TLS、备份恢复、灾备、容量、告警、RTO/RPO/SLO 与演练记录。
4. **Dify 闭环未完成验收**：接口存在不等于 Dify 已交付；完整 Dify 栈在本机内存条件下未安全启动，需在资源满足后完成“Dify → FileBay → RAGFlow”的授权、撤回、过期和错误令牌回归。

### P1：内部试用体验与一致性

1. 已统一 RAGFlow 管理工作区地址为 `http://127.0.0.1:13080/ragflow/`；不再使用或发布旧的 `19080` 浏览器端口。
2. Dify 的 nginx 与插件调试端口已在独立私网编排中明确清空；Dify 不形成第二个浏览器入口。
3. 新发布使用“发布记录 + 索引绑定”的同事务状态切换；历史试用数据会在严格的当前、有效、同 profile、同 dataset 条件下受控纠偏，并留存 `knowledge.index_binding.reconciled` 审计事件。
4. 模型供应商页面可配置模型，但当前没有可用嵌入模型；该配置缺口已经由真实检索验证暴露，不能用空结果或模拟结果掩盖。

## 五、建议的验收与推进顺序

1. 在 RAGFlow 配置可用的嵌入模型并完成验证；不要把仅可用于聊天的 LLM 当作嵌入模型。
2. 轮换既有 RAGFlow 专用密钥，并继续保持不在应用配置或 Git 中持久化。
3. 在合成脱敏数据上重新执行并留档：资料提交 → 六项审核 → 发布 → RAGFlow 解析/索引 → FileBay 检索/引用 → 撤回/过期阻断 → Dify 调用。
4. 补齐跨账号、跨空间、过期、下架、无效令牌、RAGFlow 不可用和重试的自动化与人工验收记录。
5. 通过试用门禁后，再以业务优先级扩展连接器、知识图谱、智能体、质量运营和行业场景；不要将上游 RAGFlow 原生功能直接计入 FileBay 已治理能力。

## 六、核验限制

- 本次只使用本机合成脱敏环境，未访问真实业务数据或凭据。
- 未执行真实 Dify 链路，因为 Dify 容器未运行；原因是本机可用内存低于安全启动完整服务栈的阈值。
- 本轮已在隔离容器中执行知识模型、目录和检索的定向 Go 测试；宿主机无 Go 工具链，未执行全仓 Go 测试。
- RAGFlow 的解析、模型、智能体等上游能力只有在被 FileBay 的权限、生命周期和审计链路覆盖后，才能作为 CheersAI FileBay 的正式受控能力对外承诺。
