# FileBay 企业知识库需求基线：工具能力、数据源与准入治理

- 状态：需求整理稿，待产品/业务/合规评审确认
- 编制日期：2026-07-17
- 依据：《00-企业AI知识库落地全生命周期详细实施方案 V1.0》第七章、第九章；`docs/adr/0001-cheersai-knowledge-base-ragflow.md`
- 适用范围：FileBay 知识治理层、RAGFlow 检索处理层、后续 CheersAI 问答与工作流接入

## 1. 结论与产品边界

FileBay 不应被定义成“文件上传后交给 RAGFlow 的中转页”，而应成为企业知识的**治理主库**：负责数据源登记、分类分级、责任人、版本、审批、有效期、权限、发布、下架、审计和运营闭环。RAGFlow 只负责已批准脱敏知识的解析、切分、索引、检索和引用候选；它不是权限、版本或正式内容的权威来源。

本需求基线的硬约束如下：

1. 未脱敏原件及其本地绝对路径不得上传至 FileBay、RAGFlow、Dify、模型服务或日志系统；脱敏必须在 CheersAI Desktop/浏览器本地完成。
2. 任一接入方式（手工上传、数据库、API、文件库、公开网页）都必须先创建并通过“数据源台账”准入；没有责任人、来源依据、密级和更新策略的数据不得进入待导入清单。
3. “上传完成”“索引完成”和“正式可检索”是不同状态。只有审批通过、在有效期内、权限已生效、引用验证通过且索引可用的版本，才能进入正式检索。
4. 数据库连接器只允许以最小权限、只读账号读取批准的视图/表或接口；连接凭据只保存到密钥管理系统，业务库和审计表只保存 `secret_ref`，不保存明文密码、令牌或连接串。
5. 下架、撤权、过期须先同步阻断在线检索与引用，再异步删除 RAGFlow 中的派生文档、分块、向量与缓存。

## 2. 当前实现与本次需求的差距

当前 FileBay 知识模块已覆盖：知识空间、客户端脱敏声明、不可变修订、来源授权标识、二人审批、发布快照、RAGFlow 索引任务、失败重试基础和审计事件。它是“受控文件进入索引”的纵向闭环。

要满足第七、九章，还需补齐以下治理能力：

| 能力 | 当前情况 | 本次需求结论 |
| --- | --- | --- |
| 数据源台账 | 只有单次上传的 `source_authorization`，没有数据源实体 | 新增数据源主档、责任人、适用范围、更新周期、审批依据、密级等必填字段 |
| 分类分级 | 没有统一分类字典和密级策略 | 新增业务、内容、生命周期、场景四类分类，以及公开/内部/受限/禁止入库四级规则 |
| 文件元数据 | 仅有标题、MIME、修订及脱敏声明 | 将数据源、业务域、内容类型、责任人、生效失效、版本、适用范围、密级绑定到文档/发布快照 |
| 准入审核 | 已有基础审批 | 拆分来源、内容、权限、敏感、格式、发布六项审核，并留存证据与抽检结果 |
| 数据库接入 | 尚无连接器与字段映射 | 增加只读连接、查询/视图白名单、字段映射、增量游标、脱敏规则、抽取审计与停用机制 |
| 检索问答 | 尚未提供 Gateway、引用和反馈闭环 | 后续实现授权检索、引用展示、反馈纠错、无答案问题和运营统计 |
| 运维与审计 | 有索引任务与基础审计 | 补齐监控告警、回退、运行日志、数据源同步日志、召回/无答案/纠错分析 |

## 3. 数据源台账：所有接入方式的强制准入条件

### 3.1 数据源类型与建设前动作

| 数据源类型 | 典型内容 | 建设阶段必须确认的要素 |
| --- | --- | --- |
| 制度库 | 制度、办法、通知、细则 | 现行版本、生效日期、审批依据 |
| 流程与作业手册 | 流程图、步骤指引、SOP | 当前适用范围、异常处理、更新周期 |
| 产品资料 | 产品说明、参数、费率、规则 | 参数时效、渠道适用范围 |
| 培训资料 | 课件、考试题、讲义 | 适用对象、培训时间、是否仍为现行口径 |
| 常见问答 | 历史问答、热线问答、内部答疑 | 去重后的标准问法、最终标准答案 |
| 案例资料 | 典型案例、处理示例、复盘 | 已脱敏、背景/处理/结果完整 |
| 工单记录 | 客服工单、服务单、问题单 | 已脱敏、无效对话筛除、标准处理逻辑提炼 |
| 外部公开材料 | 官网、监管公开问答、公开说明书 | 公开可用性、抓取/下载日期、引用方式 |
| 数据库/业务系统 | 经批准的结构化业务数据、问答/规则视图 | 数据所有者、只读范围、字段含义、更新游标、脱敏规则、查询授权 |

### 3.2 `knowledge_data_source` 必填字段

下表是数据库中“数据源主档”的最低字段集。创建数据源时必须全量填写；值缺失、格式不合法或枚举不符合规则时不得保存为“待导入/已启用”。

| 字段 | 类型/规则 | 业务要求 |
| --- | --- | --- |
| `source_code` | 字符串，租户内唯一；建议“业务域-内容类型-序号” | 数据源编号，不得重复 |
| `name` | 正式名称，禁止“最新版本/最终版”等模糊名称 | 数据源名称 |
| `source_type` | 枚举：`policy`、`procedure`、`product`、`training`、`faq`、`case`、`ticket`、`public_material`、`database`、`api`、`file_repository` | 数据源类型 |
| `business_domain_code` | 关联业务分类字典 | 所属业务域，如零售、风控、运营、人力、财务 |
| `content_type_code` | 关联内容分类字典 | 制度、流程、产品、培训、问答、案例、工单摘要、公开材料等 |
| `source_department_id` | 组织部门引用 | 明确到一级或二级部门，禁止写“业务部门” |
| `content_owner_id` | 用户/岗位引用，不可为空 | 归口责任人，对正确性、适用范围、生效失效负责 |
| `maintenance_owner_id` | 用户/岗位引用，不可为空 | 日常维护人，对更新、格式、目录、归档负责 |
| `effective_at` | 日期时间；制度/规则类必填 | 生效日期 |
| `expires_at` | 日期时间或空；空时必须有 `review_frequency` | 失效日期；无固定日期时按周期复核 |
| `review_frequency` | 枚举：`weekly`、`monthly`、`quarterly`、`event_triggered` | 更新/复核周期 |
| `security_level` | 枚举：`public`、`internal`、`restricted`、`prohibited` | 密级或使用级别 |
| `approval_basis_ref` | 审批编号/发文号/会议纪要引用，不存敏感正文 | 审批依据 |
| `applicable_scope` | 结构化范围：组织、部门、岗位、项目、渠道、地区等 | 适用范围，既用于审核也用于 ACL 上限 |
| `source_authorization_ref` | 授权证据引用/哈希，不含本地路径 | 证明数据有权纳入当前知识库 |
| `source_format` | 枚举或 MIME；数据库源填 `structured` | 原文件格式/结构化来源类型 |
| `searchability_status` | 枚举：`searchable`、`ocr_required`、`not_searchable` | 是否可全文检索、是否需 OCR |
| `current_status` | 枚举：`draft`、`pending_review`、`approved`、`enabled`、`suspended`、`expired`、`archived` | 数据源本身的治理状态 |
| `created_at`、`updated_at` | 系统维护 | 台账创建与最后更新时间 |

以下字段对数据库/API 类数据源为额外必填项：

| 字段 | 规则 |
| --- | --- |
| `connector_type` | 如 `postgresql`、`mysql`、`mssql`、`oracle`、`rest_api`；需通过适配器白名单 |
| `secret_ref` | 仅保存密钥管理系统引用；不得保存明文账号、密码、Token、完整连接串 |
| `read_scope` | 仅允许批准的只读视图、表、字段或版本化 API 资源；禁止通配全库读取 |
| `query_template_ref` | 固化并评审的参数化查询/同步模板引用；禁止用户任意 SQL |
| `schema_version` | 字段映射所依据的结构版本 |
| `field_mapping_json` | 源字段到知识字段的白名单映射，包含标题、正文/摘要、主键、更新时间、分类等 |
| `incremental_cursor_field` | 变更时间、递增 ID 或 CDC 位点；首次全量与后续增量必须可区分 |
| `data_retention_rule` | 抽取副本、日志、索引派生数据的保留和删除规则 |
| `mask_policy_version` | 客户端/受控接入器使用的脱敏策略版本；含敏感字段时不能为空 |
| `last_sync_at`、`last_success_cursor` | 同步状态，只由任务写入 |

禁止将本地绝对路径、数据库密码、访问令牌、客户个人信息、完整 SQL 参数值或原始未脱敏记录写入台账、审计日志、RAGFlow 元数据。

### 3.3 文档、修订与数据源的关联要求

`knowledge_document` 必须关联一个 `data_source_id`；不能以自由文本“来源”替代来源主档。每次 `knowledge_revision`/发布快照必须冻结以下治理快照：

- 数据源编号、业务分类、内容分类、密级、适用范围与来源授权证据引用；
- 归口责任人、日常维护人、审批依据、生效日期、失效日期/复核周期；
- 文档主题、版本号、修订关系（修订/替代/补充）、内容哈希、脱敏策略版本和脱敏清单哈希；
- 文件类型、可检索状态、OCR 结果与关键页抽检结论（若适用）；
- 发布时的 ACL 策略版本、发布代次与 RAGFlow 索引配置版本。

任何数据源责任人、适用范围、密级、更新周期变动，必须在 **1 个工作日** 内更新数据源台账及尚未归档知识的当前元数据；若变化会扩大访问范围，必须创建新的候选发布快照并重新审批。

## 4. 分类、分级、权限与生命周期需求

### 4.1 分类字典

系统需提供可治理的分类字典，管理员维护字典项、停用状态、排序和适用数据源类型；历史发布记录保留分类快照。

| 分类维度 | 最低字典项 |
| --- | --- |
| 业务分类 | 零售、对公、风控、运营、客服、财务、人力；允许企业扩展 |
| 内容分类 | 制度、流程、产品、培训、常见问答、案例、工单摘要、外部公开材料 |
| 生命周期分类 | 草稿、待审核、已发布、已失效、已下线、已归档 |
| 场景分类 | 查询、解释、步骤指导、培训辅导 |

### 4.2 密级与准入策略

| 等级 | 准入条件 | 审核与时限 | 使用范围 |
| --- | --- | --- | --- |
| 一级公开 `public` | 来源清晰、内容完整、责任人明确 | 归口负责人；2 个工作日内 | 全员可见 |
| 二级内部 `internal` | 责任人、生效日期、版本号齐全 | 归口负责人；3 个工作日内 | 指定部门或岗位 |
| 三级受限 `restricted` | 审批依据、权限标签、适用边界齐全 | 归口负责人 + 风险合规；5 个工作日内 | 指定岗位或项目组 |
| 四级禁止 `prohibited` | 个人隐私、敏感客户资料、未脱敏工单、未审批材料 | 不进入正式库；必要时仅进本地脱敏处理区或受控审计备查区 | 不参与正式检索 |

访问控制必须按组织、部门、岗位、项目、资料级别及适用范围做交集判定；RAGFlow 元数据过滤只能做纵深防御，不能代替 FileBay/Gateway 的授权判定。

### 4.3 生命周期与时限

| 场景 | 系统必须动作 | 时限 |
| --- | --- | --- |
| 到期/被替代 | 正式区转失效区，阻断前台检索与引用 | 当日 |
| 风险下架 | 立即阻断、保留证据、补录原因和事件编号 | 4 小时内 |
| 新版替换 | 新版经审批后上线；旧版归档并记录替代关系 | 1 个工作日内 |
| 历史归档 | 归档源文件、审批依据、发布记录和版本关系；不参与检索 | 2 个工作日内 |
| 月度复核 | 校验失效区/归档区一致性，列出逾期责任人 | 每月最后一个工作周 |

下架资料若要恢复，必须重新经过内容、权限与发布审核；不允许直接把旧索引状态改回“可检索”。

## 5. 准入、审核、发布和反馈闭环

### 5.1 提交流程

```text
数据源台账登记并通过准入
  -> 业务提交人上传客户端脱敏产物/受控连接器生成候选数据
  -> 待审核区
  -> 格式、来源、敏感、内容、权限审核
  -> RAGFlow 解析、索引与引用验证
  -> 发布审核与抽检
  -> 当前有效、可检索的正式发布
  -> 反馈/错答/越权事件
  -> 修订、下架或归档
```

业务提交人只能提交待审核资料，不能直接发布或绕过审核修改现行知识。每个文件只表达一个主题；制度/流程/规则类文件必须全文可检索；扫描件必须先 OCR 并抽检关键页；工单、案例和问答必须先完成本地脱敏和标准化提炼，不能整批原样导入。

### 5.2 元数据与文件提交硬校验

提交知识时，除数据源台账已存在外，表单/API 必须填写或继承：标题、业务域、内容类型、来源部门、归口责任人、生效日期、适用范围、版本号、修订关系、密级、来源授权证据和脱敏声明。培训资料还必须填适用时间、适用对象及现行口径说明；超过 50 页的文档必须提供内容摘要与适用范围说明。

### 5.3 六项审核清单

| 审核项 | 审核内容 | 必留证据 | 不通过处理 |
| --- | --- | --- | --- |
| 来源审核 | 来源合法、授权可用于当前项目 | 来源说明、来源部门、授权/快照引用 | 退回数据源责任人 |
| 内容审核 | 正确、现行、无口径冲突 | 审核意见、适用范围、版本结论 | 退回/标记失效 |
| 权限审核 | 无越权暴露风险 | 密级、开放范围、限制条件 | 降级、拆分或禁止入库 |
| 敏感审核 | 无个人、交易、审计等敏感信息泄露 | 脱敏记录、删减依据 | 脱敏、删减或禁止入库 |
| 格式审核 | 文件格式、命名、目录、元数据合规 | 格式检查和元数据检查结果 | 退回重整 |
| 发布审核 | 引用验证、RAGFlow 索引、抽检和有效期完整 | 发布单、抽检记录、发布时间 | 延后发布/退回整改 |

一级公开、二级内部资料发布前至少抽检 3 个典型问题；三级受限资料至少抽检 5 个，并验证不同岗位的权限隔离。相同主题在相同适用范围内只允许一个“当前已发布”版本。

### 5.4 反馈、运营与审计

前台需支持检索、问答、引用查看、收藏和结构化反馈；反馈必须区分知识、检索、权限、体验四类。后台/治理台需支持数据源、导入任务、权限、监控告警、版本切换、目录、元数据、审批、有效期复核、上下架和统计报表。

至少记录以下审计与运营指标：会话/请求标识、授权结论、命中文档/修订/发布版本、引用、人工复核、数据源同步状态、任务日志、文档召回次数、无答案问题、反馈类型、纠错结论、下架事件和回退记录。审计默认记录标识和哈希，不记录未脱敏正文、完整本地路径或明文凭据。

## 6. 功能需求清单（按优先级）

### P0：必须与当前知识闭环一起补齐

1. 数据源台账：创建、编辑、停用、查看、责任人变更和必填字段校验。
2. 数据源到知识空间/文档/修订的强关联；无已批准数据源不得上传待审核知识。
3. 业务、内容、场景、生命周期分类字典；四级密级与发布范围校验。
4. 上传/API 的治理元数据表单与校验：责任人、适用范围、生效/失效、版本、审批依据、修订关系。
5. 六项审核记录、审核意见、驳回整改与发布抽检记录。
6. 到期自动阻断、手工紧急下架、替代关系、归档和事件编号。
7. 审计事件、数据源操作日志和基础运营统计；所有敏感数据遵守本地脱敏与最小留存。

### P1：数据库/API/文件库接入与可运营性

1. 数据库/API/文件库连接器注册、密钥引用、连通性测试、只读范围和字段映射管理。
2. 受控全量/增量同步，支持游标、幂等、失败重试、暂停、恢复、对账和删除传播。
3. 结构化记录到“知识文档/问答/规则”的转换模板；工单/案例/FAQ 的脱敏、去重和标准答案提炼工作流。
4. OCR、表格解析、格式质量检查、内容摘要和可检索性校验。
5. 搜索/问答引用展示、召回调优、典型问题回放、反馈回灌和无答案问题治理。

### P2：生产化增强

1. Knowledge Gateway 授权检索、返回结果二次校验、引用完整性清单和审计关联。
2. 组织/部门/岗位/项目/密级的细粒度 ACL，同步身份源和撤权实时生效。
3. 数据源 SLA 看板、保鲜提醒、告警、容量/性能监控、备份恢复、索引蓝绿和回退演练。
4. 多模态、同义词、知识推荐、复杂工作流，以及经独立 ADR 评审后再接入 Dify。

## 7. 数据库接入的专门约束

数据库不是“连上就能同步”。每个数据库数据源还必须满足以下验收条件：

1. 已书面确认数据所有者、归口责任人、日常维护人、用途、密级、适用范围、合法来源与授权依据。
2. 只读服务账号仅能访问批准的视图/字段；禁止 `SELECT *`、跨库扫描、写权限和用户任意 SQL。
3. 字段映射明确区分：主键、标题、正文/摘要、分类、版本、生效/失效、更新时间、权限标签、敏感字段；敏感字段默认不抽取。
4. 每条同步记录都可追溯到源系统标识、抽取时间、映射版本、内容哈希和对应数据源台账；不记录源库密码或未脱敏值。
5. 首次全量、后续增量、删除/失效同步和失败重试均有幂等键、任务日志和人工暂停开关。
6. 同步前后进行抽样：字段完整性、脱敏效果、权限范围、版本/日期正确性、RAGFlow 引用可用性；未通过不得自动发布。
7. 数据源停用、权限收窄、字段含义变化或源系统不可用时，必须停止新增同步；已发布内容按有效期、撤权和下架规则处理。

## 8. 验收标准与下一步

本需求进入开发前，应由产品、业务归口、知识管理员、技术、安全/合规共同确认数据源台账字段、分类字典、审核角色和时限。首批每一种数据源至少选择一条脱敏样本完成端到端验收。

首轮验收最低通过条件：

- 不存在无数据源、无责任人、无密级、无适用范围、无版本/生效信息的正式知识；
- 禁止入库资料、草稿、失效、已下架、已归档资料的在线召回数为 0；
- 任一正式引用能回溯到数据源、文档、不可变修订、审批和发布快照；
- 数据库连接器无法读取未批准对象，凭据不出现在界面、日志、审计和 RAGFlow 元数据中；
- 受限资料通过至少 5 个问题的授权隔离测试；
- 下架或撤权后，在线检索阻断符合约定时限，且形成事件和删除传播记录。

建议下一开发项不是继续扩展展示页面，而是先实现 **P0 数据源台账 + 文档元数据 + 准入审核清单**；它们是后续数据库接入、RAGFlow 索引、Dify 调用和生产问答都必须依赖的控制面。
