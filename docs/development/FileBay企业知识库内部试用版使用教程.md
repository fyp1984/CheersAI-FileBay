# FileBay 企业知识库内部试用版使用教程

> 适用对象：知识提交人、知识管理员、审核人和 Dify 应用管理员。
> 适用版本：FileBay 企业知识库内部试用版。
> 本文是操作导航，不替代企业的制度审批、脱敏规范和密级管理制度。

## 1. 先理解：这个系统不是“上传文件就能问答”

FileBay 是知识的治理入口，负责决定一份资料能否进入、谁能看到、是否仍有效；RAGFlow 只负责对**已经发布**的资料建立索引和提供检索候选；Dify 只能经 FileBay 的授权接口检索，不能直接读取 RAGFlow。

一份资料要成为可检索知识，必须走完下面的闭环：

```text
登记数据源 → 管理员启用数据源 → 提交已脱敏文件 → 六项审核
→ 创建索引任务 → 索引成功 → 管理员生效发布 → 受控检索
```

所以，看到“上传成功”并不代表已经可以被问答使用。它只是进入审核队列。

## 2. 登录与页面结构

本地试用地址：<http://127.0.0.1:13080/knowledge>

登录后会看到左侧的“知识库工作台”。日常使用时只打开当前要做的一个模块，不需要填写整页表单。

| 左侧入口 | 谁通常使用 | 用来做什么 |
| --- | --- | --- |
| 开始使用 | 全部有权限用户 | 只选择现在要做的事情，不显示管理表单 |
| 我要查资料 | 业务用户、客服、运营、培训人员 | 输入问题，查看有效资料的引用依据 |
| 我要提交资料 | 资料提交人 | 按提示完成资料夹、来源登记和脱敏文件提交 |
| 待我处理 | 知识管理员 | 审核来源、完成六项审核、处理索引和发布 |
| 知识管理 | 管理员 | 查看资料台账、数据库接入和 Dify 授权；业务用户不需要进入 |

## 3. 第一次使用：把一份制度文件变成可检索知识

我们以“客户投诉处理规范.md”为例。开始前，请确认文件已经在本地完成脱敏；原始文件、客户信息和本地绝对路径都不应上传。

### 第一步：创建知识空间

进入“我要提交资料”，点击“1. 创建资料夹”。在创建表单中填写：

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| 空间名称 | 客户运营知识库 | 同一业务主题的知识容器 |
| 空间说明 | 客户投诉、服务流程和常见问答 | 建议写清使用边界 |

点击“创建私有知识空间”。

**成功标志**：下方“知识空间”列表出现新空间；系统同时建立一个私有仓库来保留知识文件和不可变修订。

### 第二步：登记文件来自哪里

回到“我要提交资料”，点击“2. 告诉系统资料来自哪里”，只需填写三项：

| 字段 | 示例 |
| --- | --- |
| 知识空间 | 客户运营知识库 |
| 这批资料叫什么 | 客户投诉处理制度库 |
| 资料属于哪一类 | 制度、办法、通知 |

点击“提交来源，等待管理员启用”即可。系统自动生成内部编号，并带入责任人、密级、有效期、来源授权等治理信息；业务人员不需要理解或填写这些技术字段。

**注意**：登记完成后，数据源仍不能直接上传。另一位管理员需要在“已登记数据源”列表点击“审核并启用”。

**成功标志**：数据源状态显示为“已启用”，并在“第三步：提交脱敏资料”的“已启用数据源”下拉框中出现。

### 第三步：提交已脱敏文件

来源被管理员启用后，回到“我要提交资料”，点击“3. 上传脱敏文件”，只填写下面五项：

1. 选择知识空间；
2. 填写知识标题，例如“客户投诉处理规范”；
3. 选择刚才已启用的数据源；
4. 选择本地已经脱敏的文件；
5. 勾选“我确认该文件已在客户端完成脱敏后再提交”。

点击“提交待审核”。如果这是新主题，保持“修订已有文档”为“新建逻辑文档”；如果是在更新一篇已存在的制度，选择对应文档，并在“版本关系”中按需填写修订版本和替代关系。

系统会自动从文件识别类型，并从数据源继承来源授权、适用范围和脱敏策略，再进行文件签名、格式与脱敏清单校验。

**成功标志**：页面提示已提交审核，文档出现在下方“知识文档”列表，治理状态为待审核。

### 第四步：完成六项审核

使用**另一位管理员**登录，进入“待我处理”，点击“完成六项审核”。提交人不能审核自己提交的资料。

按顺序通过下列六项：

| 审核项 | 审核时重点确认什么 |
| --- | --- |
| 来源审核 | 来源部门、授权依据和数据源是否正确 |
| 内容审核 | 内容是否准确、仍是现行口径、适用范围是否明确 |
| 权限审核 | 密级与可见范围是否匹配，不会扩大访问范围 |
| 敏感审核 | 已脱敏，无个人、客户、交易或其他禁止内容 |
| 格式审核 | 文件类型、版本、标题和可检索性是否合格 |
| 发布审核 | 是否适合被检索引用，是否需要抽检或补充说明 |

六项全部显示“通过”后，点击“批准并创建索引任务”。发现问题时点击“驳回修订”，不要通过后再靠下架处理。

**成功标志**：审核项均为通过，且“发布与索引”出现对应索引任务。

### 第五步：处理索引并让知识生效

进入“待我处理”，点击“处理索引并发布”。在“最近索引任务”中查看任务状态；需要人工触发时点击“立即处理”。索引成功后，在“发布快照”中点击“评测通过并生效”。

只有此时，该版本才进入正式检索范围。

**成功标志**：发布快照显示为当前生效，索引状态成功。

### 第六步：检索并核对引用

回到“我要查资料”，输入一个能从文件中找到答案的问题，例如：

```text
客户投诉首次响应的时限是什么？
```

检索结果应显示标题、可展示的正文片段、发布编号、修订编号和相关度。请检查引用是否来自刚刚发布的版本，而不是历史资料。

**成功标志**：返回引用且内容与制度一致。未找到资料时，系统会明确提示没有当前用户有权查看的有效知识，而不会编造答案。

## 4. 更新、替代和下架

| 场景 | 正确操作 | 不要这样做 |
| --- | --- | --- |
| 制度修订 | 在“内容管理”选择已有文档，提交新修订，再重复审核、索引和生效 | 直接覆盖旧文件或跳过审核 |
| 新版完全替代旧版 | 填写“替代版”关系，让新版审批后生效 | 删除旧版本以掩盖历史 |
| 发现风险或错误 | 在“发布与索引”点击“下架并撤销检索” | 等下一次定期审核才处理 |
| 数据源到期 | 在“数据接入”执行“检查并停用已到期数据源” | 继续用已到期资料新增内容 |

下架会先阻断检索，再撤销索引；历史修订、审批证据和审计记录仍会保留，以便追溯。需要恢复的资料必须重新审核，不能直接改回可检索状态。

## 5. 数据库数据源：只给管理员的操作

数据库接入不是把数据库地址和密码填进页面。只有经批准的、已脱敏的**只读视图**可以接入。

进入“流程外管理”下的“数据库接入（技术管理员）”。这不是业务人员的日常步骤；除知识空间和数据源名称外，管理员还需要填写或选择：

- 连接器类型，例如 `mysql`；
- 密钥引用，例如 `secret-ref:env/KB_MYSQL_DSN`，而不是密码或完整连接串；
- 已审批的查询模板引用；
- 只读范围、字段映射、增量游标字段和保留规则。

管理员启用数据源后，先点击“预览脱敏视图”，确认读取记录、字段和待审核文档数量正确，再点击“执行增量同步”。同步得到的内容仍然进入同一套六项审核和发布流程，不能直接对外检索。

**绝对禁止**：填写密码、访问令牌、原始表名、任意 SQL、未脱敏字段或本地路径。

## 6. Dify 接入：只检索，不直连

管理员进入“流程外管理”下的“Dify 应用授权”，填写应用名称、Dify 知识库标识、固定知识空间及最高密级，点击“创建 Dify 授权”。系统只显示一次应用密钥，请在受控密码库中保存。

给 Dify 配置的外部知识检索端点为：

```text
http://127.0.0.1:13080/api/knowledge/external/retrieval
```

请求使用 `Bearer` 应用密钥，并且请求中的 `knowledge_id` 必须与本次绑定的 Dify 知识库标识一致。FileBay 会按该应用的固定空间和密级再次过滤结果，再调用 RAGFlow；Dify 不会得到 RAGFlow 密钥、原始路径、数据库连接信息或未授权内容。

## 7. 常见问题：先看这里

| 现象 | 常见原因 | 处理方法 |
| --- | --- | --- |
| “已启用数据源”没有可选项 | 数据源未被另一位管理员启用 | 回到“数据接入”完成审核并启用 |
| 无法批准审核 | 六项审核未全部通过，或审核人就是提交人 | 换另一位管理员完成全部审核 |
| 上传被拒绝 | 文件未脱敏、类型不受支持、文件内容与扩展名不匹配 | 仅提交已脱敏的 PDF、DOCX、PPTX、XLSX、MD、TXT，并检查扩展名 |
| 搜索不到刚上传的内容 | 仍在审核、索引未成功或尚未生效 | 按“审核中心 → 发布与索引”完成全部步骤 |
| Dify 返回 401/授权失败 | 密钥错误、未使用 Bearer 格式或 `knowledge_id` 不匹配 | 核对应用绑定、一次性密钥及请求标识 |
| 不该看到的内容被返回 | 应立即按风险事件处理 | 先“下架并撤销检索”，再复核数据源密级、范围和审核记录 |

## 8. 一次演示的最小检查清单

- [ ] 创建一个私有知识空间；
- [ ] 登记一个普通文件数据源，并由另一位管理员启用；
- [ ] 上传一份本地已脱敏的 Markdown 或 PDF；
- [ ] 由另一位管理员完成六项审核并批准；
- [ ] 处理索引任务，确认发布快照生效；
- [ ] 使用一个业务问题检索，并核对标题、片段和修订引用；
- [ ] 下架该发布快照，再次检索确认不再返回该内容。

完成以上八项，才说明“数据源 → 审核 → 索引 → 发布 → 检索 → 下架”的最小闭环跑通。
